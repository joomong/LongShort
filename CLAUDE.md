# Repository working guide

## Current implementation

- `cpp-engine/`: C++17 engine, XML compiler, metrics, GA and Drogon HTTP server.
- `frontend/`: Next.js 14 / React / Zustand / uPlot; TypeScript and Vitest/Playwright.
- Personal workspace: `~/longshort_workspace/config.yaml`, `alphas/`, `modules/`, `research/` and generated `.longshort/` (including HTTP request temporary files in `.longshort/uploads/`). Built-in modules stay in `cpp-engine/src/modules/`; platform `modules/README.md` is the module guide. `tools/run_engine.py` discovers and incrementally builds the modules beside the chosen config before starting the server.
- The single web start button and Shift+Enter run GA: unique candidate evaluation, round-start/candidate/round-end streaming, dynamic worker scheduling and gross IS Sharpe. The web shows Stats plus live round tabs; defaults are 20 threads, first search 200, stop round 40 and stop alphas 400. See `cpp-engine/docs/math_contract.md` for budgets, compatibility and light detail requests.
- Large heatmaps normalize complete date rows in web workers; server plot/distribution serialization is parallel.
- GA Stats and completed/stopped rounds include a combined batch for their successful candidates, replayed in candidate order through the signal combination (each alpha normalized to gross 1, then summed). Visible IDs follow table order; internal IDs remain stable. Reclicking the selected row does nothing for every result count. Multi-alpha results stay in performance detail; instrument signal plots are available only for a single-alpha result, which opens on them when its GA finishes or stops and switches to performance with Signals/Performance tabs (saved-result loads open on Performance). Selected daily performance loads after its round finishes, avoiding evaluation-time replay.
- Python tools generate module/catalog metadata and run independent validation. Production field values are read by C++ Arrow/Parquet.

See [README.md](README.md), [documentation and research index](docs/README.md), [module SDK](modules/README.md) and [data configuration examples](cpp-engine/examples/datasets/README.md).

## Working conventions

Make reviewable changes, preserve user work and run checks appropriate to the changed behavior. Read the implementation before relying on historical reviews. Reports dated 2026-09-08 describe an earlier state; later reports explain which findings were fixed or reclassified.

Preserve existing running servers. When isolated integration tests need a server, use a separate port and stop only processes started for that test. Do not modify shared source data to make tests pass. Synthetic fixtures belong in a temporary directory or the tracked test fixture directory.

The user may explicitly authorize parallel developer work; coordinate file ownership and perform independent reviews in that case. Follow the user's requested scope and existing authorization.

## Engine and data contracts

- The original team's fixed-notional approximation (not an exact share ledger) uses close-to-close holding PnL, or cached total holding returns for thin-v1, one-way turnover costs and additive cumulative PnL/drawdown. `backtest.execution_price` accepts `close` (general default), `ohlc4` or `vwap` (selectable per run; the active thin example defaults to close). VWAP fills at raw same-day `vwap` with the same fixed-notional leg `(close / VWAP - 1)` and the same validity/unfilled policy as OHLC4, using exact `vwap/high/low` (vwap or close outside [low, high] is unfilled). OHLC4 is raw `(open + high + low + close) / 4`; gross PnL adds actual market trade weight × `(close / OHLC4 - 1)` to holding PnL. Corporate position transfers themselves generate neither this execution leg nor market turnover fees. Target notional and fee conventions are unchanged. Execution has no interval mode or implicit target delay; default fee is 1.5bp one-way (turnover × rate). Performance metrics (summary, yearly, drawdown, IS-Sharpe sort, GA fitness) use gross returns (before fee); `timeseries.cumPnl` is net, `cumPnlGross` gross.
- OHLC4 requires exact-alignment `open/high/low/close` sources and eagerly loads them even with restricted `selected_fields` or lazy declarations. Missing fields/files/columns or as-of execution prices fail loading; never substitute close execution. Raw OHLC stays untouched. A missing OHLC cell under `carry` blocks trading and freezes/reserves existing exposure while observed close marks and holding returns continue normally; `error` fails a required trade. Finite but inconsistent OHLC ranges follow the same carry/error unfilled-order policy. Nonpositive/infinite prices refuse relevant positions. The shared `simulator_config` applies execution pricing to ordinary, combined and GA paths. `/api/config.executionPrice` exposes the default and `executionPrices` the supported options. Simulate/GA accept a per-request executionPrice, echoed in results; the frontend selector stores it in runSettings for replay. Older APIs show their fixed execution value with selection disabled.
- Delay is explicit in alpha XML only. New editor XML contains delay="1". Preserve saved XML delays; never insert an additional engine shift.
- `avgBet` means average held-symbol count; `minBet` means minimum held-symbol count. Legacy JSON keys differ from internal names; see `json_serializer.cpp`.
- Prices remain intact outside the universe. Rank/Zscore and target normalization use the signal-date mask. The current pipeline output is masked, normalized and executed on the same bar.
- Thin-v1 (`base.cache/manifest.json` layout): raw `base_data.parquet` supplies prices; cached `returns.parquet` is the CRSP-style total return (default signal `returns` and the sole holding P&L input) and `adj_returns.parquet` is the split-adjusted price-only return (signal field `adj_returns`). A thin cache that still has `returns_total.parquet` (old naming, e.g. rc2f3) is rejected at config load and must be rebuilt. `adj_factor` supplies the split share basis; thin `events.parquet` only retires sources and adds destination positions at builder-valued ratios. `universe.name` selects a named interval membership set, and event destinations are loaded transitively. The loader rejects top-level `events:` and `backtest.corporate_actions:` with thin-v1. Example filenames can retain historical labels; use the YAML cache path and manifest to identify the current release and unresolved estimates. See `cpp-engine/examples/datasets/README.md` and `docs/data_contract.md`.
- Generic nonthin long/wide datasets and nonthin wide `base.cache` remain loadable. For these inputs, XML `returns` is derived from close; the thin total-return P&L and position moves are absent. `backtest.missing_close_policy` defaults to `carry` and freezes held positions without a quote, then recognises the accumulated close move on resumption; `error` fails fast. The config loader rejects any key it does not read (`Unknown config key '<path>'`), including the old `events:`, `backtest.corporate_actions:`, `default_delisting_return`, and `stale_quote_settle_bars` settings. The current contract is in `docs/data_contract.md`; the data/P&L research notebook preserves historical accounting evidence. `build_events.py` remains a cache_v21 builder dependency.
- `derived/returns_total.parquet` in cache_v2.1 is a builder intermediate for the old ledger path; thin-v1 publishes that total return as `returns.parquet` at the cache root. Keep their contracts distinct.
- `sim_start_index` separates module/target warmup from trading. No historical holdings or fees arise in warmup; initial execution fees belong to the trading period.
- Combined alphas always use normalized equal-alpha contributions (each alpha's signal row becomes gross-1 weights before summing) and final portfolio normalization, accumulated in a deterministic alpha order. The former `combined_mode`/`combinedMode` raw switch was removed (2026-10-15).
- C++ data loading aligns stable symbol IDs and timestamps. Wide fields can be lazy; aliases share one buffer. `returns` is close-derived for nonthin layouts and a cached field for thin-v1. AFL catalog names are metadata, not a request to load every factor.
- `base: {cache, groups}` registers default price and group fields. A nonthin cache expands into eager wide `BaseData/{open,high,low,close,volume,VWAP,marketCap_USD}.parquet`; thin-v1 reads long `base_data.parquet`, cached `returns.parquet` (total) and `adj_returns.parquet` (split-only). Both use `base_groups` (`sector`, `industry`) with as-of alignment. A missing base file or group panel with no finite code on a priced bar fails startup. Rebuild the group panels for the chosen cache when its dates or IDs change.
- `<neutralize group="sector|industry"/>` demeans the signal within the group read from the `sector`/`industry` field on the signal date: the signal-date universe mask is applied first (like rank/zscore), only finite values with a finite code >= 0 enter the group mean, everything else becomes NaN, a singleton group yields 0, and there is no scaling or minimum size — identical to the team `cs_group_neut_1d`. Unknown or unregistered groups are compile errors; `neutralize` is a reserved tag for discovered modules.
- `alignment=asof` uses the most recent row at or before each target timestamp, retaining nulls in that row. Timestamps must represent data availability. The user chose restart-based data refresh without version tracking or automatic reload. `end_date: latest` (also the YAML default) trims only the all-NaN close tail over selected symbols; explicit dates retain their requested range.

## Commands and validation

Launch with `python3 cpp-engine/tools/run_engine.py --config /path/to/config.yaml`. Dependency prefix/PyArrow options are in [the build guide](docs/build_and_validation.md). CMake builds should use a separate build directory.

The current engine uses `~/longshort_workspace/config.yaml` on port 50007; the web remains on 50006. `tools/restart_engine.py` defaults to that user's workspace config, `.longshort/build/longshort-server` and `.longshort/logs`. Keep source/data examples in the platform. Relative data/catalog paths resolve against the chosen config directory, so the current workspace uses an absolute shared AFL catalog path.

Full C++ checks: build with `LONGSHORT_BUILD_TESTS=ON`, then run CTest. To run HTTP tests without skipping, generate a fixture using `cpp-engine/tools/make_http_test_fixture.py` and provide `LONGSHORT_TEST_SERVER` and `LONGSHORT_TEST_CONFIG`. Commands and validation scope are in [the build guide](docs/build_and_validation.md); use the current run for test counts.

`cpp-engine/tools/run_logic_tests.py` is an in-memory core harness; it excludes Parquet/config/HTTP integration. Do not report its results as full-server validation. Its `--with-tool-tests` also runs the module/catalog tooling checks.

In `frontend/`: `npm ci`, `npm test`, `npm run build`, `npm run lint`. Production helpers must not be replaced with test stubs. `npm run test:e2e` supports `PLAYWRIGHT_PORT`, `PLAYWRIGHT_CHROME_PATH`, `PLAYWRIGHT_USE_BUILD`, and `PLAYWRIGHT_ENGINE_URL`. Use the last variable for live C++ integration and distinguish it from fixture-based browser tests.

Current API routes: `/api/config`, `/api/simulate`, `/api/ga/stream`, `/api/alphas` (plus `/api/alphas/{name}` DELETE and `/api/alphas/{name}/results[/batch|/rows/{id}]`). Saved alphas live in the top-level YAML `alphas_dir` (default `alphas`, relative to the config; published as `/api/config.alphasDir`) as `<name>/{alpha.xml, metadata.yml, results/, positions/}` with levels `xml|results|positions`; existing names are rejected (409). `positions/<id>.parquet` holds the order targets (normalized `desired_weights` per trading bar, AlphaPos-equivalent), not post-execution held weights. `alphas_dir` must be a local filesystem with RENAME_NOREPLACE (ext4/xfs/btrfs/tmpfs; sshfs/NFS are rejected at startup); each running save flocks its `.<name>.tmp-*` dir and startup removes only unlocked ones, so engines can share one `alphas_dir` (`lslocks` shows live saves; never delete `.tmp-*` dirs by hand while engines run). Preserve actual XML when saving an expanded alpha. Raw signal payloads have sampling metadata and are separate from normalized positions.
