# Repository working guide

## Current implementation

- `cpp-engine/`: C++17 engine, XML compiler, metrics, GA and Drogon HTTP server.
- `frontend/`: Next.js 14 / React / Zustand / uPlot; TypeScript and Vitest/Playwright.
- `modules/`: per-config user modules. `tools/run_engine.py` discovers and incrementally builds them before starting the server.
- Python tools generate module/catalog metadata and run independent validation. Production field values are read by C++ Arrow/Parquet.

See [README.md](README.md), [current logic/data report](docs/logic_completion_2026-09-11.md), [module SDK](modules/README.md) and [data configuration examples](cpp-engine/examples/datasets/README.md).

## Working conventions

Make reviewable changes, preserve user work and run checks appropriate to the changed behavior. Read the implementation before relying on historical reviews. Reports dated 2026-09-08 describe an earlier state; later reports explain which findings were fixed or reclassified.

Preserve existing running servers. When isolated integration tests need a server, use a separate port and stop only processes started for that test. Do not modify shared source data to make tests pass. Synthetic fixtures belong in a temporary directory or the tracked test fixture directory.

The user may explicitly authorize parallel developer work; coordinate file ownership and perform independent reviews in that case. Follow the user's requested scope and existing authorization.

## Engine and data contracts

- Close-to-close holding PnL, one-way turnover costs, fixed-book additive cumulative PnL/drawdown. D0=0 and D1=1 are both implemented; default D1 and default fee 5bp remain.
- Data delay in XML and execution mode are independent. New editor XML defaults to delay=0. Preserve explicit saved XML delays.
- `avgBet` means average held-symbol count; `minBet` means minimum held-symbol count. Legacy JSON keys differ from internal names; see `json_serializer.cpp`.
- Prices remain intact outside the universe. Rank/Zscore and target normalization use the signal-date mask. Under D1 the masked targets execute on the next bar.
- Missing-close accounting (`backtest.missing_close_policy`, default `carry`): a held position with no valid close is frozen at its last observed mark (no trade, no fee, zero P&L) and recognises the full move when quotes resume; orders for a quote-less asset are blocked (no scaling up of the rest). `error` restores the legacy fail-fast. Delistings settle only from an explicit `securityEndDate` in the `events:` file: the settlement opens on the bar after the end date and closes on the first bar without an observed quote (quotes continuing past the end date are still valued and reported as `postEndDateQuoteBars`); the return is priced on the settlement bar from the deal terms, `R = (cash + ratio·close_successor(t))/mark − 1` (`cash_col`, `successor_ratio_col`), falling back to the file's `return_col` only when the proceeds cannot be priced (a declared stock leg whose survivor is not quoted on that bar is never priced from the cash leg alone), then to `default_delisting_return` (default 0 = documented assumption, sensitivity -1); `stale_quote_settle_bars` settles a *held* position with no event after N missing bars. Settlements carry no fee and are reported in `missingData`. Only the stock leg `h·ratio·close_successor/mark` transfers to the successor without a trade; the cash leg is realized (`successorConversions`/`convertedGross` = transferred weight; `settledGross`/`defaultDelistingGross` stay on the exposure basis `|h|`, the cash share of it for mixed deals). Deal terms must be in the price cache's share basis: the cache close is restated for later splits, so the generator anchors each leg to the cache (`k = as-traded DB price / cache close` on the target's last mark date and on the settlement bar) and emits `cashPerShareCache`/`successorRatioCache`; the loader compares `successorCacheClose` at `successorCacheCloseDate` with the panel and refuses to start when the events file is stale against the cache (`eventsPriceChecks`/`eventsPriceChecksSkipped` in `/api/config`). Regenerate the events file after any cache rebuild. The events file is built from xfeed by `cpp-engine/tools/data/build_events.py` (co_acthist terms → `cashPerShare`, successor, ratio, cache-unit columns; acquirer prices never after the settlement bar) after `refresh_master.py` refreshes end dates; a DB end date is adopted only when it agrees with the trading item's last DB price, otherwise the local master date; outputs live under `data/` (gitignored). Inputs without gaps/events are bit-identical to the pre-policy engine.
- Corporate actions (`backtest.corporate_actions`, docs/corporate_actions_engine_2026-09-17.md): an optional cache-unit ledger (`engine/ca_ledger_cache.parquet`, exported by `cache_v21/loader.py export_ca_ledger` from the raw `events/ca_ledger.parquet`) books, on the ex-date bar and against the previous mark `m`, a cash leg `w·cash/m` (pre-tax, 100% for long and short, no share change) and a stock leg that creates a child weight `w·ratio·child_close/m` recognised as P&L at once; the child joins the book after that bar's execution (no trade, no fee) and is thereafter an ordinary asset (strategy target, or NaN → 0 → sold at the next execution with the normal fee; no quote → carried). A child with no quote on the ex-date waits for its first quote (`unpriced_child: pending`; no future price on the ex-date); a child outside the panel is `distribution_unpriced`; ledger when-issued/estimate values are used only when the child never quotes and are flagged (`distributionsEstimated`, `legsEstimated`). Legs dated on the parent's settlement bar are booked against the pre-settlement exposure and mark; a ledger cash leg beside an events cash leg and a stock leg naming the events successor are count-only (`legsDeferredToEvents`); merger/rename/relist rows are refused (the `events:` file owns them). Rights/warrants use the stock-leg path; with `expiryDate` present a pending right lapses at 0 on the first bar after expiry and a held frozen right settles at R=−1 (priority: events settlement > expiry > stale-quote); `auto_exercise: true` refuses to start. Staleness anchors (parent ex/before, child) must match the panel or the engine refuses to start. Inputs without a ledger are bit-identical to the pre-ledger engine. Never add `returns_total` on top of engine P&L: the ledger already carries the distribution value (double counting). Unconfirmed P&L (rc2f Y1, docs section 9): the export keeps unbookable rows as marker rows (`markerReason` no_cash_amount / no_child, status unresolved, values NaN) instead of dropping them; on a held parent the engine records `corporateActions.unconfirmed` items (`unresolved_leg`, `default_settlement`, `estimate_value`, `pending_dropped`, with `weightBefore`), `pnlUnconfirmed`, `timeseries.unconfirmedWeight`, without changing any P&L; `backtest.corporate_actions.unresolved_policy: strict` fails the run (HTTP 400) on the first such bar, `warn` (default) only reports. A stock/rights leg whose child is outside the panel but carries `childValuePerShareCache` (P10 (2)(3)(4), the export's value per parent share) is booked as P&L without a position (`ledgerValueCash`, `distributionsValueOnly`), the same path as `returns_total` flag 3. A leg the ledger flagged as an estimate stays an estimate whatever priced it (a quote-priced child with an estimated ratio or ex-date is `estimate_value(child_close:<estimateReason>)`, the export column says ratio/date/value); the numbers are the quote's. The published `events/corporate_actions.parquet` is raw-unit: for a split_adj panel use `loader.py export_events` → `engine/events_cache.parquet` (written by `export_wide`), which restates cash/ratio with the split factors and re-anchors the guard on the export panel.
- Costs (`backtest.costs.borrow`, off by default): short financing Σ|w_short|·rate/day_count·calendar days from an interval table or `default_rate`, taken from net P&L only (gross unchanged); with neither table nor default the run reports `costs.borrowApplied=false`. No broker figure is a default.
- `derived/returns_total.parquet` (cache_v2.1 rc2) is the pre-tax cash-style holding return `(shares·close_t + cash + Σ ratio·child_close)/close_prev − 1` from the corporate-action ledger on every dividend/distribution day (no reinvestment, no D/P threshold); `retFlag` 0 price_only / 1 cash / 2 distribution / 3 estimate (incl. lineage-link overlap, new-id share-basis conversion) / 4 unresolved (incl. old/new-id ratio conflict, implausible linked first return |ret|>0.5, rows after a stale ledger cut). The vendor `divAdjFactor` stays in `factors/dividend.parquet` for cross-checks only and is never a fallback for defective factors.
- `sim_start_index` separates module/target warmup from trading. No historical holdings or fees arise in warmup; initial execution fees belong to the trading period.
- `combined_mode=normalized` uses normalized equal-alpha contributions and final portfolio normalization. `raw` preserves the original signal-scale weighting. Both accumulate in a deterministic alpha order.
- C++ data loading aligns stable symbol IDs and timestamps. Wide fields can be lazy; aliases share one buffer. `returns` is reserved for the existing derived close return. AFL catalog names are metadata, not a request to load every factor.
- `base: {cache, groups}` expands into the eager wide datasets `base_prices` (open, high, low, close, volume, vwap = VWAP.parquet, cap = marketCap_USD.parquet) and `base_groups` (sector, industry) ahead of user `datasets:`; `datasets:` is optional only when `base:` exists. `base_groups` uses as-of alignment (the last known classification carries forward when the cache grows; symbols absent from the panel stay unclassified until a rebuild). A missing base file fails the start, and so does a group panel with no finite code on a bar that has a close (a panel that starts too late or was built for another cache). Group panels are static broadcasts of the current master classification (`industry` = CIQ `simpleIndustryDescription`, 74 labels nested in the 11 sectors) built by `cpp-engine/tools/data/build_group_panels.py` into `data/groups/<cache>/`; regenerate them after any cache rebuild.
- `<neutralize group="sector|industry"/>` demeans the signal within the group read from the `sector`/`industry` field on the signal date: the signal-date universe mask is applied first (like rank/zscore), only finite values with a finite code >= 0 enter the group mean, everything else becomes NaN, a singleton group yields 0, and there is no scaling or minimum size — identical to the team `cs_group_neut_1d`. Unknown or unregistered groups are compile errors; `neutralize` is a reserved tag for discovered modules.
- `alignment=asof` uses the most recent row at or before each target timestamp, retaining nulls in that row. Timestamps must represent data availability. The user chose restart-based data refresh without version tracking or automatic reload. `end_date: latest` (also the YAML default) trims only the all-NaN close tail over selected symbols; explicit dates retain their requested range.

## Commands and validation

Launch with `python3 cpp-engine/tools/run_engine.py --config /path/to/config.yaml`. Dependency prefix/PyArrow options are in [the build guide](docs/module_discovery_build_2026-09-09.md). CMake builds should use a separate build directory.

Full C++ checks: build with `LONGSHORT_BUILD_TESTS=ON`, then run CTest. To run HTTP tests without skipping, generate a fixture using `cpp-engine/tools/make_http_test_fixture.py` and provide `LONGSHORT_TEST_SERVER` and `LONGSHORT_TEST_CONFIG`. Exact commands and latest counts are in [the data/build report](docs/logic_completion_data_2026-09-11.md).

`cpp-engine/tools/run_logic_tests.py` is an in-memory core harness; it excludes Parquet/config/HTTP integration. Do not report its results as full-server validation. Its `--with-tool-tests` also runs the module/catalog tooling checks.

In `frontend/`: `npm ci`, `npm test`, `npm run build`, `npm run lint`. Production helpers must not be replaced with test stubs. `npm run test:e2e` supports `PLAYWRIGHT_PORT`, `PLAYWRIGHT_CHROME_PATH`, `PLAYWRIGHT_USE_BUILD`, and `PLAYWRIGHT_ENGINE_URL`. Use the last variable for live C++ integration and distinguish it from fixture-based browser tests.

Current API routes: `/api/config`, `/api/simulate`, `/api/ga/stream`, `/api/alphas`. Preserve actual XML when saving an expanded alpha. Raw signal payloads have sampling metadata and are separate from normalized positions.
