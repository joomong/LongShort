# 기존 close-to-close 계산의 논리 오류 수정

이 문서는 리팩토링 이전의 계산 오류 수정 단계와 당시 검증 결과를 기록한다.

사용자 요청에 따라 현재 종가 체결·단리 고정 북 모델에서 확정된 구현 오류를 먼저 수정했다. 데이터 소스·YAML 확장과 체결 모델 추가는 이 패치의 범위가 아니다.

## 적용

- 보유 또는 체결 예정 포지션의 종가가 결측/비유한/0 이하이면 계산 오류를 반환한다. 이전처럼 보유 손익을 조용히 0으로 만들지 않는다. 미보유·미체결 종목의 결측은 수익에 기여하지 않는다. 두 시뮬레이션 경로가 동일한 종가 수익 함수를 사용한다.
- 시계열 Mean/Zscore/Delay/Decay의 init이 버퍼·누적 상태를 초기화한다. 같은 객체를 재실행하거나 자산 수를 바꾸어 실행해도 이전 상태가 섞이지 않는다.
- 요약·연도별 MDD는 초기 누적손익 0을 고점 후보에 포함한다. 프론트 낙폭은 초기 자본 대비 단리 손실 폭으로 계산하며, 첫날 손실도 포함한다.
- IS 시작일이 데이터 뒤이면 과거 전체를 IS로 사용하는 대신 빈 IS 구간을 반환한다.
- GA population/generations=0 및 시뮬레이터의 잘못된 차원·mode·fee, 입력 신호 행렬 차원을 검사한다.

정상 종가 데이터의 손익 시점, D0/D1 의미, 기본 XML delay, 거래비용, 연환산 상수는 기존 의미를 유지한다. 손계산 회귀 사례에서 D1 신호는 다음 종가에 체결되고 이후 종가 변동으로 손익을 얻으며, 롱/숏 반전 비용은 편도 거래량 합에 비례하는 것을 검증했다.

## 검증

- 실제 엔진 소스와 기존 테스트 파일 15개를 g++로 직접 컴파일했다. 119개 중 118개 통과, 1개 실패.
- 신규 상태 초기화/종가 손익·비용/결측 종가/낙폭/기간 경계/GA 입력 회귀 사례는 모두 통과했다.
- 기존 2,000알파 스트레스, NumPy golden, XML/파이프라인, SIMD AVX2 및 현재 버전 체크포인트 round-trip도 통과했다.
- 유일한 실패는 기존 Checkpoint.ModuleInputLoadsLegacyFixtureV0. 엔진 코드를 포함하지 않은 최소 프로그램에서도 아카이브 헤더를 읽는 시점에 같은 오류가 난다:

```text
Boost headers=1_85 supported archive version=19
Archive header only, no engine code: unsupported version
```

- 실패 픽스처의 아카이브 버전은 20이다. 픽스처/ModuleInput 직렬화/체크포인트 코드는 이번 패치에서 수정하지 않았다. 이 검증은 전체 테스트 성공을 뜻하지 않는다.
- 변경한 실제 TypeScript 계산 함수 본문을 TypeScript 5.9.3으로 변환하여 Node에서 초기 손실, 고점 대비 단리 낙폭, 음수 equity, 초기 자본 검사, 수수료 복원 등 7개 독립 계산 검사를 통과했다.
- 프론트 전체 Vitest/브라우저와 HTTP 서버는 실행하지 않았다. 기존 frontend/lib 모듈 부재 및 전체 CMake 의존성 문제는 별도 과제다.
- git diff --check 통과.

## 남은 논리 검토

사용자가 `avgBet`=평균 보유 종목 수, 화면 `minBet`=기간 중 최소 보유 종목 수가 맞다고 확인했다. 현재 계산·표시도 이 정의와 일치하므로 minBet은 계산 오류 목록에서 제외하고 계약 문서를 정정했다. 계산 코드는 변경하지 않았다.

combined raw 합산의 의미·합산 순서 결정성, simStart의 실행 범위 정의는 아직 남아 있다. 이 패치가 기존 리뷰의 모든 항목을 해결한 것은 아니다. 데이터 로더 타입/중복 검사와 신규 연결 구조는 이후 데이터 작업에서 다룬다.
