## 메모리 효과

아래는 제거한 값 버퍼의 크기 계산이며 프로세스 RSS 실측이 아니다. `T`는 전체 bar 수, `T'`는 plot 대상 bar 수, `N`은 종목 수, `F`는 해당 구간의 유효 nonzero 신호 수다.

- 미사용 gross/N 배열: SimulatorOutput 하나당 `8*T` bytes와 매 bar gross/N 계산 제거.
- run_from_signals 행 복사: `4*N` bytes scratch와 `T*N`번 float 복사 제거.
- D0 전용 실행: 사용하지 않는 previous target `8*N` bytes 제거.
- 요약/연도 통계: 해당 finite return 구간당 cumulative 배열 `8*n` bytes 제거. 분산·tail Sharpe 등에 실제 필요한 finite return 배열은 유지.
- plot 구간 복사: `4*T'*N + 8*T'` bytes의 값 버퍼와 행 벡터 객체 제거.
- histogram 평탄화: `4*F` bytes 이상(capacity 여유분 별도)의 값 버퍼 제거.
- 프론트: alpha/combined마다 읽히지 않는 IS/OS 누적손익 record 두 개, 합계 plot 기간만큼의 날짜 key/value 항목 제거. JavaScript 객체 byte 수는 런타임에 따라 달라 고정 수치를 주장하지 않는다.

예를 들어 plot 대상이 1,000 bar × 1,000종목이고 모든 신호가 유효 nonzero이면, plot 복사와 histogram 사본의 float 값만 약 8MB다. 결과 JSON과 실제 사용 중인 원본 신호 행렬은 여전히 필요하다. 이번에 제거한 것이 아니다.

- 루트는 GA/serializer 구현의 소비자·난수 수명·필터/빈 구간·legacy JSON 키를 별도 대조했다.
- 검증 담당자는 일치하는 Boost 환경, 전체 unit 빌드와 서버 호출부 타입 검사, 메모리 수명을 확인했다: [검증 기록](refactor_2026-09-09_validation.md).
- 리뷰 과정에서 GA simStart 문자열 읽기를 없애면 기존 타입 오류 검증도 없어지는 것을 발견했다. 값 저장과 capture만 제거하고 asString 검증 부수효과는 같은 위치에 보존했다.
- 공유 실행 경로의 raw signal callback 자동 검증 공백을 지적받아 bar 순서/횟수, raw/NaN 신호, 수집값 일치, replay에서 callback/collector를 호출하지 않는 기존 계약 테스트를 추가했다.
- 반영 후 검토 범위에서 미해결 회귀/필수 수정 사항은 발견하지 못했다. 이는 아래 미검증 범위까지 보증한다는 의미는 아니다.
